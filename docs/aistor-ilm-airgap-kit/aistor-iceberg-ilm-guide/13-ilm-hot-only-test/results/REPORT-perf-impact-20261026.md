> 규칙: 기존 규칙(1d 시험용 3개)을 유지한 채 `perf-` 규칙 3개를 **병합** 적용 — Transition **0d** → `WARM-TIER` (기존 객체 전부가 즉시 대상)

**요약**: 기존 버킷에 정책을 거는 작업 자체는 서비스 쓰기에 영향이 없고 테이블 정의도 바뀌지 않는다.
비용은 **전이된 데이터를 읽을 때의 지연(소량 조회 약 2배, 대량 스캔 +30~40%)** 과 **Scanner 가 기존 객체를 훑는 시간**이다.
대량 백로그가 있는 버킷에 처음 걸 때는 처리 시간을 객체 수로 추정하고(기본 속도 기준 4.5개/s → 100만 개 ≈ 2.6일, 단일 노드 기준),
필요하면 Scanner 속도를 한시적으로 올렸다가 **반드시 원복**한다.

## 2. P-1 전이 진행

| 지점 | 기본 속도 (규칙 적용 후) | `fastest` (규칙 적용 후) |
|---|---|---|
| 1% | 13초 | 10초 |
| 50% | 433초 | 10초 |
| 90% | 794초 | 25초 |
| 100% | **914초** | **25초** |
| Scanner 객체 방문 수(증가분) | 10,386 | 34,955 |
| 전이 실패 · 누락(`missed_immediate`) | 0 · 0 | 0 · 0 |

- 기본 속도에서는 1분마다 100~400개(파티션 폴더 1~4개)씩 줄었다 → Scanner 는 **폴더 단위로 순회**하며 사이클마다 일부만 방문한다.
- 규칙 적용 13초 만에 첫 폴더가 전이된 것은 Scanner 가 마침 그 버킷을 돌던 중이었기 때문이다. 대기 시간은 버킷 크기와 사이클 위치에 따라 달라진다.
- 전이 대기·진행 작업 메트릭(`minio_node_ilm_transition_{pending,active}_tasks`)은 0 에서 움직이지 않았다 — 15초 샘플 간격보다 빨리 소화됐다.

## 3. P-2 · P-3 지연 (1분 간격, ms)

| 구간 | 회 | 오류 | 쓰기 p50/p95 | 고정 파티션(100 파일) 읽기 p50/p95 | 메타데이터(`files`) 조회 p50 | 전체 스캔 p50 | 정합성 |

| 규칙 전 (기준선) | 15 | 0 | 482 / 649 | 755 / 827 | 216 | 17,972 | 3/3 |
| 전이 중 | 19 | 0 | 488 / 673 | 920 / 1,086 | 241 | 23,202 | 4/4 |

- 쓰기는 항상 Hot 에 새 파일을 만들므로 전이와 무관하다 (전이 중 p95 도 같은 수준).
- 메타데이터 조회 증가(+62 ms)는 `metadata/` 가 아니라 **스냅샷·매니페스트 수 증가**(프로브가 매분 커밋) 영향이다 — `metadata/` 전이는 0건.
- 1d 시험의 0d 스모크에서 본 "소량 조회 약 2배"(291 → 590 ms)와 합치면, Warm 경유 비용은 **요청당 고정 지연 + 대역폭**으로 보인다 → 작은 파일을 많이 읽는 쿼리일수록 상대 비용이 크다. compaction 으로 파일 수를 줄이면 완화된다.
